# POS 0.1.0 - Release candidate notes

**Status: Draft.** This is release preparation, not an announced or tagged
release. Nothing is shipped until the release PR is reviewed and merged into
main, and the user explicitly authorizes tagging and publishing.

## First local prototype

POS 0.1.0 establishes a local-first Tasks and Projects engine with a CLI and
basic Ratatui screens. It is not yet a complete personal information system.

Included capabilities:

- Tasks: title, description, due date, priority, status, project assignment,
  completion/reopen, deletion and validated atomic editing.
- Task search, filtering and sorting, with human-readable and JSON CLI output.
- Projects: add, list, rename, archive/unarchive and deletion that preserves
  tasks by unassigning them.
- SQLite storage with versioned additive SQLx migrations, constraints and
  integration tests.
- Data check (integrity and foreign keys), online SQLite backup, validated
  restore into a new path, and versioned JSON export (format_version 2).
- Source-based Linux installation, consistent Cargo workspace versioning,
  GitFlow branches and automated CI.

## Known limitations

- POS is a **local prototype**, not a production multiuser server.
- pos-server is a placeholder. Authentication, permissions, device identity,
  offline synchronization and network APIs are not implemented.
- Other planned modules (mail, calendar, notes, Git, files, etc.) are not
  functional.
- The Ratatui layout is intentionally basic. Task Engine v2 metadata is
  primarily managed using the CLI.
- No automatic backup scheduling or off-device retention, JSON import,
  upgrade rollback, standalone packaged downloads or guaranteed cross-platform
  binaries.
- SQLite and JSON backups are not encrypted; secure them yourself.
- Release engineering is Linux/source-install oriented; there are no
  distribution packages, system services or automatic update mechanisms yet.

## Installation and upgrades

On Linux with a Rust toolchain installed, clone the repository and run:

```sh
bash scripts/install-local.sh
~/.local/bin/pos --version
```

The script compiles the pinned Rust 1.99.1 workspace client in release mode
and installs to ~/.local/bin/pos without sudo. It does not change PATH or your
database. Use --prefix /some/dir to choose a different installation root.

To replace a previously installed POS binary, explicitly use --upgrade:

```sh
bash scripts/install-local.sh --upgrade
```

Without --upgrade, the installer refuses to overwrite an existing executable.
The installer never alters your SQLite data. A new version can, however, run
additive SQLx migrations on first launch. Back up real data before upgrading:

```sh
pos data check
pos data backup "$HOME/pos-before-0.1.0.sqlite3"
```

Use a unique filename for each backup, and preserve copies off-device.
If you need to recover, restore a backup to a new path and inspect it first:

```sh
pos data restore "$HOME/pos-before-0.1.0.sqlite3" --output "$HOME/pos-recovered.sqlite3"
pos --db "$HOME/pos-recovered.sqlite3" data check
```

Never overwrite a live POS database file or remove SQLite WAL files to perform
a downgrade. There is no automatic rollback of migrations.

- [x] cargo fmt, strict Clippy, workspace tests and full workspace build pass.
- [x] Build the optimized client using cargo build --release --locked.

- [x] Test local install, no-overwrite default and explicit --upgrade in an
      isolated temporary installation root.
- [x] Confirm migration tests from existing older database schemas pass.
- [ ] Verify GitHub Actions on the release/0.1.0 -> main PR.
- [ ] Review and merge release PR into main (**not performed as part of
      release preparation**).
- [ ] Confirm final main commit, authorize and create tag v0.1.0.
- [ ] Back-merge any release-only changes into develop using a separate PR.

The last three steps require explicit approval and are not automated here.
